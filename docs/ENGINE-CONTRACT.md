## Transcript

Format: JSONL — one JSON object per line, appended as the turn progresses

| block | required keys |
|---|---|
| `text` | `type`, `text` |
| `tool_use` | `type`, `id`, `name`, `input` |
| `tool_result` | `type`, `tool_use_id`, `content`, `is_error` |

- A `user` entry carrying tool_result blocks is a TOOL RESULT, not a new user prompt. Hooks split "this turn" on real user prompts; conflating the two makes every turn look like it started fresh.
- tool_result.tool_use_id must match the id of the tool_use it answers.
- is_error must be true on a failed tool call — gates use it to tell a clean run from a failed one.

## Hook control protocol

- block via exit code 2 — stderr is fed back to the model, the action is blocked
- block via JSON — `{"decision":"block","reason":"..."} on stdout`
- pass — exit 0, stdout ignored (or injected as context on UserPromptSubmit)
- claims-gate.sh and stop-checks.sh emit the JSON form; vague-delete-gate uses it on PreToolUse. Both paths must work.
